# 통합 수업 창 설계

처음 배우는 사람이 한 창에서 원인과 결과를 비교하도록 구성했습니다. [Don Norman의 설명](https://jnd.org/affordance-conventions-and-design-part-2/)을 참고해, 눈에 보이는 개념 구조·조작 결과·익숙한 관례·제약을 아래처럼 적용했습니다. 실제 초보 학습자 대상 사용성 연구를 수행했다는 의미는 아닙니다.

| 원칙 | 적용 |
|---|---|
| 발견 가능성 | 단계, 색공간, 속도를 숨겨진 메뉴 대신 항상 보이는 버튼으로 표시 |
| 개념 구조 | 인지 → 판단 → 제어, 영역 → 위치 → 힘의 순서를 고정 |
| 대응 관계 | 같은 프레임의 BEFORE를 왼쪽, AFTER를 오른쪽에 표시. 조절기는 해당 결과 옆에 배치 |
| 피드백 | 선택 버튼 강조, 재생/정지 문구, 시각·프레임 번호, 즉시 갱신되는 결과 |
| 제약 | 재생 중 한 장 넘기기 비활성화, 색 최솟값/최댓값 역전 방지, PID 입력 범위 제한 |
| 복구 가능성 | 기본값 복원·처음부터·위치 탐색. 탐색과 설정 변경 시 PID 상태 초기화 |
| 가독성 | 영상 안의 작은 영문 설명·성능 수치 제거. 한국어 제목과 핵심 결과를 Qt 텍스트로 표시 |

## 실행 구조

- `start.sh`: 운영체제에 맞는 ROS와 프로젝트 가상환경·설치 환경을 불러온 뒤 `ros2 run session_1 classroom` 실행.
- `lesson_player.py`: SQLite bag을 읽기 전용으로 열고, 카메라 프레임과 그 시점 이전의 조향 기록을 연결. 0.5초 이상 지난 피드백은 없는 값으로 처리.
- `classroom.py`: GUI에서 시간·정지·속도·탐색 관리. QThread에서 모델 추론과 bag 읽기를 수행해 화면 조작이 막히지 않도록 분리.
- 같은 장면의 값 조절과 단계 전환은 기존 모델 결과를 재사용. 처리 중에는 작업을 무한히 쌓지 않고 최신 재생 시점으로 진행.
- 일시정지·탐색 직전에 시작된 작업의 늦은 결과는 화면에 덮어쓰지 않음.
- 녹화 파일 직접 재생 방식이라 별도 ROS 토픽은 발행하지 않음. 토픽 통신 수업에는 기존 개별 노드를 사용.
- SQLite `.db3` rosbag에 대응. 파일을 분할 저장한 경우 시간순으로 연결. 다른 저장 형식은 안내 오류 표시.

PID 결과는 기록된 피드백을 사용한 재계산이며, 새 제어값에 차량이 반응하는 폐루프 시뮬레이터가 아닙니다.

## 조향 안정화 비교

각도 그림과 설명을 제거하고 오차가 0에 가까워지는 과정에 초점을 맞춥니다.

- `error_plot.py`: 녹화된 오차 이력과 교육용 모의 수렴 곡선을 별도 모드로 표시. 녹화 오차는 PID가 사용하는 목표값과 센서값의 차이이며 차선 픽셀 오차와 구분합니다. 입력 없음은 빈 구간으로 표시하고 탐색/설정 변경 시 이력을 초기화합니다.
- `error_response.py`: 같은 초기 오차 20, 가상 관성계 `x'' = 3u - 2x'`, 0.02초 간격으로 12초를 계산. P와 PID의 제약은 동일합니다. 임의의 교육용 예시이며 실제 차량 모델이 아닙니다. 어떤 설정에서나 0으로 수렴한다고 보장하지 않습니다.
- `pid_comparison.py`: 오른쪽 막대는 계속 실제 녹화 입력에 대한 P/PID 출력입니다. 모의 곡선의 출력과 혼동하지 않도록 제목과 안내를 분리했습니다.
- P/I/D를 바꾸면 모의 곡선을 즉시 다시 계산하지만, 녹화된 움직임은 바뀌지 않습니다. 내부의 기존 PID 제어 계산은 유지했습니다.
